Storage layout for a single site pack
-------------------------------------

Expected files you drop here for a site:

- `site-config.yml` – declarative topology and defaults (copy or adapt from `site-config.example.yml`).
- `provision-registry.json` – generated by `/provision/apply` (optional but recommended to restore).
- `control-registry.json` – generated by `/provision/apply` (optional but recommended to restore).
- `miners.db` – optional SQLite cache for miner IP ranges (if missing, agent can seed from `site-config.yml`).
- `profiles/` – if you still use site-local profiles, place them here; otherwise rely on the global `/app/profiles` baked into the image.
- `chirpstack-devices.yml` – optional seed list for `cs-seed.py` (DevEUIs/AppKeys). Keep real values out of the public repo.

This folder is mounted read/write into the agent container so any runtime changes to the registries will land here and can be backed up into the per-site seed repo.
Per-VFD policy keys in `site-config.yml` (see the example) give you a place to version boot/auto/safehz defaults even if the current registry generation still drives the live settings.
